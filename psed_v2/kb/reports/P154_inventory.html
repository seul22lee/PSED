P154-inventory: psed_v2/ontology/ - what is there, what each file reads and writes, what still runs. Zero calls, no change (this report
and its tables only). Held-out papers (yim22, gre23, mat23): their rows are counted, not shown.

1. Files (files.csv): 20 in ontology/ (17 tracked; sources/ is gitignored) plus 7 elsewhere that write into it or read its data files.
   Ran in the last 30 commits (47fe794..HEAD, judged by their tracked outputs): export.py only (vocab.py, form.json, form_pass0.json,
   FORM.md, CODEBOOK.md in P146-P150), plus pass0_paper.py / compile.py outside the folder. pending_decide.py, merge_pending.py,
   alias_audit.py, apply_external_ids.py, entry_definitions.py, make_report.py, figures_import.py and absorption.py did not.
   Callers: check.py runs export.py --check; pass0_paper.py imports the P143 layouts from export.py; merge_pending.py imports
   pending_decide and alias_audit; everything else is run by hand; make_report.py is called by nothing.
2. Data files (data_counts.csv, rows in pending.csv, pending_decisions.csv, unmapped.csv, external_ids.csv): pending.csv 10 rows, all
   pending, 7 of them already entries in ontology.yaml (P138); pending_decisions.csv 10 rows, all rule none / pending; unmapped.csv 81
   rows (45 pilot hand rows, 36 figure-import rows; 12 belong to held-out papers); external_ids.csv 122 rows (91 sure, 31 check).
   compile.py writes none of them (writers.csv): its unmapped list is kb/compiled/<pid>.unmapped.csv. pending / pending_decisions /
   external_ids are pilot-era; unmapped.csv is fed by the figure import, whose figures.json v2 compile reads.
3. Pending flow (flow.csv, flow.txt): hand row (P83) or --labels candidate (P131b) -> pending_decide.py rules a-d (P98) -> merge_pending.py
   (P131b) -> alias_audit.py -> export.py / make_report.py. The v2 compile output does not connect: candidate(), rules a and c and the
   alias audit read only kb/pilot (gold) and figures.json; nothing reads kb/compiled/*.unmapped.csv; compile has no from_other re-key.
4. v0 report generator (v0_report.txt): ontology/make_report.py -> ontology/report.html; called by nothing; last run P132; it runs today
   (scratch copy) and exits 1 on check 11 (family electrical) and check 14 (the seven P138 duplicates).

psed_v2/kb/reports/P154_inventory.flow.txt

Pending flow (from the code and the P83 / P98 / P131b / P138 records; table: flow.csv)

Pilot sequence, unmapped label -> entry:
  1. P83, by hand: drafting a paper's gold, a concept no entry fits becomes a pending.csv row (status pending); export.py carries it into
     vocab.py as PENDING so the gold can use the id at once.
  2. P131b: a free label (gold records keyed other[<label>]) becomes a candidate row: pending_decide.py --labels "a;b" (candidate()).
  3. P98: pending_decide.py decides every row by rule a (two or more papers in kb/pilot/*.facts.csv or kb/*.figures.json), b (a Cremers
     section marked sure), c (set on an experimental run in kb/pilot/experiments.csv, or the method of an observation), d (converts_to an
     accepted entry); writes pending_decisions.csv and the status / evidence columns. "Run after a paper is added" (its docstring).
  4. P131b: merge_pending.py turns accepted rows into ontology.yaml entries and drops them from pending.csv / pending_decisions.csv.
  5. alias_audit.py (--apply) adds printed forms as aliases; 12b/12c: template definitions, then entry_definitions.py (the user's text).
  6. export.py regenerates vocab.py and the forms / codebook; make_report.py runs the 15 checks; facts.write() re-keys gold other[label]
     records to the entry's from_other label.
  The figure path is separate: figures_import.py writes unresolved figure fields to ontology/unmapped.csv (and keeps the pilot's hand rows);
  those rows are listed by make_report (check 12, section 6) and checked by check.py (P84); nothing turns them into pending rows.

Where v2 compile.py's unmapped list would enter, and where it does not connect:
  - compile.py writes kb/compiled/<pid>.unmapped.csv (100 rows for yli18, yim20, mat22: 87 quantity rows, id other with label_as_printed,
    unit and a candidate definition_quote; 13 unit rows kept as printed; compiled_unmapped.csv) and other[...] rows into
    kb/compiled/<pid>.facts.csv (82). It never writes ontology/unmapped.csv or pending.csv. Nothing reads kb/compiled/*.unmapped.csv.
  - The natural entry is step 2 (candidate()), then step 3. Both read only kb/pilot (the gold trees, kb/pilot/experiments.csv) and
    figures.json, so compiled labels and compiled papers count for nothing; a paper with no gold has no voice in rule a or c.
  - candidate() writes the definition from the first gold record's statement; compile's candidate column (definition_quote, unit as
    printed) is not used anywhere.
  - Steps 4, 6 work on ontology files only and would take a row however it got into pending.csv.
  - Compile has no from_other re-key (lists.FROM_OTHER is unused in kb/extract): a promoted free label stays other[...] in compiled facts
    unless the label is also an alias.
  - Unit rows (unit kept as printed) have no path at all: units.yaml grows by hand (P138 commit 1).
  - P138 (e894f9e) added seven entries by hand straight into ontology.yaml while their pending.csv rows stayed (pore_density, tortuosity,
    pore_volume, model_reactant, porous_sphere, porous_slab, porous_cylinder): make_report check 14 fails on exactly these.
