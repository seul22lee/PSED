## The exact function where cross-measurement identity ceases to be possible

Two points, in order:

1. **`to_kb.py:1127-1130`** — `c = json.loads(json.dumps(e))`; `c["exp_id"] = eid` or
   `"%s-C%02d" % (eid, k)`. The N cases of Fig 2a's sweep are byte-identical deep copies
   differing only in `exp_id` and `case_index`, all carrying the same full `points` array.
   From here, case *k* has no property that identifies it as the 100 C case. Corpus-wide:
   **561 swept cases, 408 without their swept quantity in `controlled`.**

2. **`to_kb.py:1236` `assign_experiment_ids`** — the id is built from
   `figure_slug(printed_figure_number, panel)` alone. `Fig2a`, `Fig2b` and `Fig2c` are three
   different slugs, so the three panels get three unrelated id families. `_events`
   (L1210-1214) then keys on `(fig_docling_index, panel_key, granularity_kind)`, which
   differs in both `panel_key` and `granularity_kind` across the three panels, so no grouping
   is even attempted.

The conditions needed to join them are present on Fig 2c (T = 100 / 300 in `controlled`) and
absent on Fig 2a/2b — so the join is unavailable in both directions under the current data,
independently of the id scheme.
