What ExperimentalCase actually is

One case carries up to 6 physical Samples under a single nominal fingerprint, and the conditions are stored on the case rather than on each realization. So ExperimentalCase is a nominal condition case — option B — not a physical experiment, sample or deposition run. Labelling it “Experiment” in a UI asserts a physical identity the data does not carry.

The physical layer is nearly absent: 16 Samples and 1 DepositionRun across 182 cases. Sample→Run is set on only a few samples, so a case that exposes a run is usually exposing the run of one of its samples.

Entity counts and link incidences are different numbers. There are 247 unique Measurements but 218 Case–Measurement incidences, so summing measurements under case cards over-counts. The relation is N:M in both directions: 22 Measurements link to more than one Case (max 10), and 131 link to none.

Measurement granularity

Every producer has at most one ResultSeries. That is not simply a sparse corpus: the records carry represents_same_measurement_as, and applying it collapses 247 Measurement entities into 235 distinct observing acts. Six acts are each rendered as three separate Measurement entities — one per panel — with the same-act relation kept as a sideband instead of as shared identity. So the entity is currently per extracted curve, while the schema's own fields describe a per observing act intent. Classification: MEASUREMENT_OVERMINTING for those, INTENDED_CARDINALITY unproven for the rest.

Recorded UI defects (not evidence about the science)

Kept separate from the entity findings, and not fixed here: the workbench's caseOfSeries returns case_ids[0], silently collapsing an N:M relation; its parentage diagnostic reports max_series_per_producer = 1 without saying that this reflects per-curve Measurement minting; and the Y representation control sets a target that the plot path does not materialize, so only x projections are actually applied.
