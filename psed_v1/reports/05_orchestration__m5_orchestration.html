Orchestration loop — KB ↔ planner ↔ executors

One entry point turns a query into a grounded, cited action by routing an intent to the right executor and writing the result back so the KB's memory grows. The planner is a keyword router today; an LLM would replace only that step.

Intents → executors: identify: process_id → KB processes + citations · predict_conformality: channel_model twin → penetration depth · optimize_dose: kb_bridge rate prior → saturation dose · warm_start: kb_bridge.warm_start → controller seed
